# bytx-skills — крипто-скиллы для ИИ-ассистентов

[English](../README.md) | **Русский**

Восемь шагов одной сделки на криптобирже: просканировать перпетуалы, посмотреть фандинг и открытый интерес,
дождаться входа, спланировать выход, 10 000 раз переиграть остаток сессии, посчитать объём от суммы, которой готовы
рискнуть, проверить по своим лимитам и отправить — по умолчанию на бумажный счёт и никогда без вашего «да».

Подключается к **любому ИИ-ассистенту с поддержкой MCP — например, к Claude**. Логика — Python-пакет с MCP-сервером
и командной строкой на библиотеке [bytx](https://pypi.org/project/bytx/); для Claude поверх есть скиллы
(`/crypto-scanner` …).

## Установка

Нужен [uv](https://docs.astral.sh/uv/) (`brew install uv`).

**Любой MCP-клиент** (Claude Desktop, Claude Code, Cursor …): добавить сервер в конфиг клиента, шаблоны —
в [`mcp-configs/`](../mcp-configs/) (запуск через `uvx --from bytx-trader@latest bytx-trader-mcp`), путей указывать
не нужно. Без uv: `pip install bytx-trader` и команда `bytx-trader-mcp`. Дальше просто говорите с ассистентом:
«просканируй крипторынок», «переключись на Bybit, риск 5 долларов на сделку», «спланируй лонг по ETH со стопом 1,5 ATR»,
«какие у меня позиции». Символы — как угодно (`BTC`, `btcusdt`, `BTC/USDT`); настройки показывает и меняет инструмент
`settings`, данные лежат в `~/bytx-trader`. Claude Desktop пишет, что сервер не запустился? Он может не видеть `uvx` — укажите в
`"command"` полный путь из `which uvx`. Можно начать и с промпта сервера
`trade_pipeline`. Инструмент `confirm` держите в режиме «спрашивать каждый раз».

**Только Claude, дополнительно:** `/plugin marketplace add byttrade/bytx-skills`, `/plugin install bytx-trader@bytx-skills`
или `cp -r bytx-skills/crypto-* ~/.claude/skills/`. Слэш-команды и срабатывание по фразам есть только в Claude;
все шаги, режимы и проверки работают в любом MCP-клиенте.

## Обновления

При запуске через `uvx` (как в шаблонах) сервер при каждом старте ассистента берёт свежий `bytx-trader` и свежий
совместимый `bytx`: исправления и новые возможности бирж приходят сами. Несовместимая версия `bytx` сама не приедет —
набор принимает одну серию (`>=0.2.2,<0.3`), новая серия приходит вместе с проверенным релизом `bytx-trader`.
При установке через `pip` сервер раз в сутки сверяется с PyPI и в первом ответе подсказывает обновиться
(`BYTX_TRADER_NO_UPDATE_CHECK=1` — выключить). Скиллы Claude из плагина обновляются вместе с маркетплейсом (`/plugin`).

## Режимы

- **paper** (по умолчанию) — живой стакан биржи, виртуальный баланс, реальные комиссии; ключи не нужны.
- **demo** — «переключись на demo» (`settings`), ключи demo биржи в окружении сервера (`BYTX_API_KEY`,
  `BYTX_SECRET`, для OKX/KuCoin/Bitget ещё `BYTX_PASSWORD`; для Hyperliquid — `BYTX_WALLET_ADDRESS` и `BYTX_PRIVATE_KEY`). В чат ключи не вставлять.
- **real** — этот пакет реальные ордера не отправляет: они идут через hosted BYTtrade MCP на [byttrade.com](https://byttrade.com).

Каждый ордер проходит три проверки в коде: PASS риск-проверки для этого тикета; `execute` ничего не отправляет и
выдаёт одноразовый токен, а `confirm` принимает токен и ваш ответ дословно (всё, кроме простого «да», отменяет);
подтверждение вызова в самом клиенте. При таймауте ордер ищется по client_id (`reconcile`) и повторно не отправляется.
Ордера отправляют только bytx и bytx-trader в выпущенном виде: изменённая установка отклоняется (лицензия bytx не
разрешает изменённые копии; восстановить — `uv cache clean` и перезапуск ассистента).

Пример с числами (BTC на Binance, 18.11.2026), описание шагов и оговорки — в [README на английском](../README.md).
